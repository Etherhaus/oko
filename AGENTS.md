# AGENTS.md — Oko

## Рабочий контекст

**Назначение.** Oko — кроссплатформенный (Linux/Windows/macOS) публичный инструмент на Rust: прогоняет серию сетевых проб к зарубежным сервисам и классифицирует блокировки — DNS-подмена, DPI/ТСПУ по SNI, блок по IP, HTTP Host-фильтрация, обрывы l4-25 (16–20/25 КБ), QUIC/UDP, плюс сравнение «напрямую vs через туннель». GUI — Slint (этап 4), по образцу ether-ovpn.

**Позиционирование.** Измерение и диагностика, **не** обход блокировок. Методика каждого теста открыта и описана честно, включая известные ложные срабатывания. Инструмент для блога и сообщества etherhaus; компаньон ether-ovpn: Ether ведёт сквозь стены, Oko показывает, где они стоят.

**Имена зафиксированы Дмитрием:** репозиторий `etherhaus/oko`, крейт на crates.io `oko-detector` (имя `oko` занято чужим крейтом), app id `io.github.etherhaus.Oko`. Бинарь называется `oko`, пакет — `oko-detector`.

**Стек.** Rust edition 2024, tokio, rustls (этап 2), clap (CLI), Slint 1.x (GUI, этап 4), ureq для DoH (HTTP/1.1, rustls, без gzip).

**Структура.**
- `src/main.rs` — точка входа: без подкоманды открывает окно, `oko probe <домен>` / `oko probe --all` — CLI. CLI остаётся навсегда — отладка и CI.
- `src/target.rs` — стартовый список целей: домен, порт, роль (service/control), записанные IP как фолбэк для сломанного резолвера.
- `src/probes/dns.rs` — системный резолвер vs DoH-эталоны; `src/probes/dns/wire.rs` — минимальный DNS-wire-кодек (A/AAAA), единственная часть DNS-пробы, тестируемая без сети.
- `src/probes/tcp.rs` — connect с таймаутом и таймингом.
- `src/probes/tls.rs` — rustls-рукопожатие с настоящим SNI, при неудаче — с контрольным на том же IP; классификация по факту ответа сервера, не по сертификату.
- `src/probes/http.rs` — plain HTTP/1.1 GET с настоящим `Host`, при неудаче — с контрольным.
- `src/probes/payload.rs` — после рукопожатия читает тело до 64 КБ и фиксирует, где оборвалось; обрыв в 16–20 КБ или ~25 КБ при неполном ответе — `KbDrop`.
- `src/probes/quic.rs` — исследовательская UDP-проба: 1200-байтный Initial с grease-версией; явный ответ сервера (Version Negotiation) — факт, тишина — `unknown`.
- `src/route.rs` — транспорт пробы: `Route::Direct` или `Route::Socks5`; SOCKS5 no-auth handshake и CONNECT, парсеры ответов с тестами.
- `src/verdict.rs` — движок вердиктов: `VerdictKind`, `Level`, `classify()`, `pick_address()`, `diff()`/`apply_diff()`; юнит-тесты на моках, без сети.
- `src/report.rs` — текстовый и JSON-отчёт (`--json`), секции payload/QUIC/туннель-дифф.
- `src/format.rs`, `src/json.rs` — форматирование длительностей и адресов, сериализация `Duration` в миллисекундах.
- `src/run.rs` — оркестрация одного прогона, общая для CLI и GUI: `run(targets, Options, progress)` → `RunReport`; `Progress` — события по ходу (контроль, старт цели, прямой отчёт, туннельный отчёт, дифф). `Options` — таймаут и SOCKS5.
- `src/gui.rs` — окно Slint: состояние `App`, движок в отдельном потоке со своим tokio-рантаймом, события через `mpsc`, UI-поток дренирует их таймером раз в 50 мс; экспорт через `rfd`.
- `src/i18n.rs` — строки интерфейса RU/EN (`Lang`, `Strings`, `apply`); текст отчётов остаётся английским, как в CLI и JSON.
- `ui/app.slint` — разметка окна: `TargetRow`, `Labels`, `Theme`, компоненты (Card, Pill, Field, Stepper, Check, TargetItem).
- `build.rs` — `slint_build::compile("ui/app.slint")`.

**Команды.**
- Сборка: `cargo build`; релиз — `cargo build --release`.
- Запуск: `cargo run` — окно; `cargo run -- probe github.com`, `cargo run -- probe --all`, `cargo run -- probe --all --socks5 127.0.0.1:1080`; `--timeout <сек>` (дефолт 5, 1..=120) — бюджет одной пробы.
- Проверки: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`.
- Отладочные переменные окна (каждая дёргает тот же колбэк, что и кнопка): `OKO_AUTOSTART=1` — начать прогон сразу, `OKO_THEME=light`, `OKO_LANG=en`, `OKO_SELECT=<индекс>` — выбрать цель, `OKO_SOCKS5=<адрес>` — заполнить поле туннеля, `OKO_EXPORT_DIR=<каталог>` — записать оба экспорта после прогона без диалога. Нужны потому, что на этой машине нет инъекции ввода (нет xdotool/wtype/ydotool, корень XWayland закрыт полноэкранным окном игры).

**Конвенции.**
- Пробы — чистые функции: (цель, конфиг) → структура результата. Никакой пробы, которую нельзя протестировать без сети, кроме тонкого слоя ввода-вывода.
- Вердикты считаются из структур результатов, а не из сокетов: `verdict.rs` тестируется на моках.
- `unknown` — нормальный вердикт, но всегда с причиной: что сошлось, что нет.
- Уровни как в NetCheck: ок / варн / бэд / неопределённо.
- `target/` не индексировать и не коммитить. Отчёты проб содержат сетевой отпечаток пользователя — в git не попадают (`*.oko.txt`, `*.oko.json`).
- Релиз и публикацию решает Дмитрий, не раньше этапа 5.

**Правила (что нельзя).**
1. Никаких привилегированных операций: без sudo, без root, без pcap/libpcap, без изменений системного сетевого стека, роутинга, DNS-настроек машины. Всё детектируется из user-space обычными сокетами.
2. Только исходящие соединения: к проверяемым целям и публичным DoH-резолверам. Никакого анализа чужого трафика.
3. Инструмент — детектор, не обходчик: фрагментация ClientHello, TCP-сегментация и любые приёмы «прохода» блокировок — вне скоупа навсегда. Пробы только наблюдают и классифицируют.
4. Никакой телеметрии и автопубликации результатов: всё остаётся у пользователя.
5. DoH-эталон недоступен — это не ошибка, а честный вердикт «эталон недоступен».
6. GUI — с этапа 4, не раньше: движок и вердикты должны быть протестированы до UI.

**Срезы.** Один этап = одна сессия, после каждого этапа стоп и отчёт (сделано / не сделано / затронутые файлы / вопросы).

**Грабли, найденные на этапе 1** (не переоткрывать заново):
- DoH-эталон обязан отвечать по HTTP/1.1 — ureq говорит только на нём. `dns.quad9.net` отдаёт 505 на HTTP/1.1 (нужен HTTP/2) и эталоном быть не может; вместо него `dns.sb`.
- `getaddrinfo` отдаёт AAAA и на машине без IPv6-маршрута. Такой connect падает с ENETUNREACH мгновенно — это локальный факт, а не блокировка. В `TcpOutcome` для него отдельный исход `NoRoute`, и вердикт этапа 2 не должен считать его `ip_block`.
- CDN-гео даёт разные легитимные IP разным резолверам: `github.com` через dns.google и через dns.sb — разные адреса, оба настоящие. Сравнение IP на равенство вердиктом быть не может.
- `dns.sb` возвращает OPT-запись в additional-секции; кодек читает только answer-секцию и это игнорирует.

**Грабли, найденные на этапе 2** (не переоткрывать заново):
- `rustls::Connection::read_tls` читает во внутренний буфер ограниченного размера (4 КБ, до 64 КБ в рукопожатии) и может взять меньше, чем ему дали. Остаток надо скармливать повторно, иначе полёт сервера (~6.5 КБ) обрывается на середине и рукопожатие висит до дедлайна. Это был живой баг: контрольный SNI на youtube.com то отвечал за 150 мс, то висел 5 с.
- Классификация — по факту ответа сервера, не по сертификату. На CDN-адресе контрольный SNI получает либо cert mismatch (Google: `*.google.com`), либо TLS-алерт (Cloudflare: alert 40) — оба означают, что рукопожатие дошло. `reached_server()` покрывает `Ok` / `ServerResponded` / `TlsAlert`.
- На ТСПУ настоящий SNI чаще уходит в тишину (timeout), а не в RST. `RstAfterClientHello` и `Timeout` — оба «сервер не ответил», вердикт один.
- Порядок правил в `classify()` важен: мёртвый контроль → `unknown` первым; дальше DNS, `ip_block`, TLS, HTTP, и только потом `ok`.
- Живая картина на 2026-11-14 (подтверждена независимо через `openssl s_client`): youtube.com, discord.com, x.com, facebook.com → `dpi_sni`; github.com, wikipedia.org → `ok`.

**Грабли, найденные на этапе 3** (не переоткрывать заново):
- `rustls::Connection::read_tls` отказывается принимать записи, когда его буфер открытого текста держит больше 16 КБ (`DEFAULT_RECEIVED_PLAINTEXT_LIMIT`), а один 16-КБ чанк расшифровывается в чуть больше. Поэтому `feed()` дренирует plaintext после каждой записи, а не только между чтениями сокета. Живой баг: github.com через туннель обрывался на 53.7 КБ с «received plaintext buffer full».
- Обрыв TLS-записи (`DecryptError`) — это конец потока, а не провал пробы: если ответ уже полный, исход `Ended` с пометкой, как поток закончился; `Failed` — только когда не прочитано ничего. Живой случай: youtube.com через туннель отдаёт 301 и следом 19-байтную запись, которую не расшифровывает ни rustls, ни OpenSSL (проверено `openssl s_client -msg` и Python `ssl`) — внешняя особенность, не наш баг.
- l4-25 считается и по телу, и по телу+рукопожатию: middlebox считает весь поток, бриф называет тело.
- На dpi_sni-целях payload-проба не запускается вовсе (`NotAttempted`, «рукопожатие не завершилось») — это честная N/A, не таймаут.
- QUIC-проба: Initial с grease-версией `0x1a2a3a4a`; Version Negotiation — единственный явный ответ. Тишина = `unknown`: UDP может молчать легитимно (NAT, провайдер).
- Туннельный прогон берёт адреса прямого прогона: иначе два прогона отличались бы и путём, и адресом. Следствие: подменённый DNS отравляет оба прогона, и дифф ничего не говорит — это написано в примечаниях отчёта.
- Живая картина на 2026-11-14 через туннель `127.0.0.1:10808` (xray): youtube/discord/x/facebook — direct `dpi_sni`, tunnel `ok` → `path_block`; github/wikipedia — `ok` на обоих путях. QUIC: youtube/discord/x отвечают Version Negotiation, github/facebook/wikipedia молчат.

**Грабли, найденные на этапе 4** (не переоткрывать заново):
- Один бинарь: `oko` без подкоманды открывает окно, `oko probe …` остаётся CLI. Поэтому `main()` не `#[tokio::main]`: CLI собирает рантайм сам, GUI держит Slint на главном потоке.
- Движок — отдельный `std::thread` со своим tokio-рантаймом; наружу только `mpsc` в обе стороны. UI-поток дренирует события таймером Slint раз в 50 мс, поэтому прогон не может подвесить окно.
- `Event::Progress(Box<Progress>)` и `Event::Finished(Box<RunReport>)` — боксы не для красоты: без них `clippy::large_enum_variant`.
- Таблица показывает вердикт прямого прогона; дифф — отдельный факт (`path_block` и т. п.) в подписи строки, в панели деталей и в JSON. `apply_diff()` меняет сам вердикт только для `service_block` → `geo_block_by_service`.
- Панель деталей — это текст CLI (`report::render_target`) в моноширинном `Text` внутри `Flickable` с `word-wrap`: строки отчёта до 130 символов, по горизонтали они не влезают ни в какую ширину панели.
- Slint 1.18: компоненты объявляются до использования; у корня компонента нет `parent`; `row` — занятое имя свойства; `Flickable` использует `content-width`/`content-height`; `TextInput.edited` без аргументов; глобальные `Labels`/`Theme` из Rust — `crate::gui::Labels`.
- Поле SOCKS5 было мертво: `TextInput` не был связан с `app.socks5`, и туннель нельзя было включить из окна. Живой прогон это и показал — таблица осталась `dpi_sni` при заполненном поле.
- Палитра (из `Theme` ether-ovpn): тёмная — фон `#16161a`, поверхность `#242428`, поле `#1b1b1f`, линия `#FFFFFF1A`, текст `#f6f5f4`, приглушённый `#8b8b93`, акцент `#fb8762`; светлая — фон `#f6f5f4`, поверхность `#ffffff`, поле `#f0efed`, линия `#0000001F`, текст `#1b1b1f`, приглушённый `#5e5e66`, акцент `#d9531e`. Уровни: ok `#7fd18b`/`#2e7d32`, warn `#f8e45c`/`#8a6d00`, bad `#f66151`/`#b3261e`, неопределённо = warn. Рамка окна — 3 px акцентом, поверхность вложена на её ширину.
- Инъекции ввода на этой машине нет: xdotool/wtype/ydotool отсутствуют, корень XWayland закрыт полноэкранным окном игры, `configure(stack_mode=Above)` niri игнорирует, синтетические `XSendEvent` winit игнорирует. Отсюда переменные `OKO_*` — они дёргают те же колбэки, что и кнопки.
